# Design System Guidelines

Edit this file with your team's real rules for how components should be
used. Claude reads this file on every review and checks the submitted frame
against it.

Replace the examples below with your actual guidelines. A few per category
is plenty -- Claude works better with specific, concrete rules than vague
principles.

## Components

- Use components only from the reference file based on their intended context and usage. Choose the appropriate variants (e.g. color, state, size, type) according to the design context. If a default value is not specified elsewhere, infer the most suitable variant from the surrounding UI and design intent.

## Color

- Don't introduce new colors outside the documented palette.

## Spacing

- Spacing follows an 8px grid (8, 16, 24, 32, 40...).

## Typography

- Use only typography components from the reference file's Typography page. Select the appropriate typography style according to the content's context, hierarchy, and design intent. Maintain consistent typography usage throughout the design and do not create custom text styles.

## Position

- Place action buttons based on the UI context.
Full Page: Bottom-left, primary button on the left.
Dialog / Modal / Dropdown: Bottom-right, primary button on the right.
Follow this pattern consistently unless a documented design guideline specifies otherwise.
